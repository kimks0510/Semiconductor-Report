# 2026-07-25 절전 해제·카카오 발송 시험 분석

## 결론

15:15 예약 작업은 정시에 PC를 깨우지 못했다. 사용자가 15:25:20에 마우스로 PC를 깨운 뒤 Windows의 `StartWhenAvailable` 설정이 놓친 작업을 15:25:22에 보상 실행했고, 카카오는 15:25:24–15:25:28에 발송됐다.

따라서 이번 시험에서 확인된 것은 다음 두 가지다.

- 예약 작업 자체와 카카오 발송: 정상
- 절전 상태 자동 해제: 실패

## 증거 타임라인

| 시각 | 확인된 사건 | 근거 |
|---|---|---|
| 15:10:05 | 전원 버튼으로 Modern Standby 진입 | Kernel-Power 이벤트 506, `Reason: Power Button` |
| 15:15:00 | 예약 시각이나 깨우기 이벤트 없음 | 시스템 전원 이벤트와 실행 로그 부재 |
| 15:25:20 | 마우스 입력으로 Modern Standby 종료 | Kernel-Power 이벤트 507, `Reason: Input Mouse` |
| 15:25:22 | 시험 작업 시작 | `trial-20260725-152522.log` |
| 15:25:24 | 반도체 카카오 발송 완료 | 반도체 실행·카카오 로그 |
| 15:25:24 | 대한항공 작업 시작 | 항공 실행 로그 |
| 15:25:28 | 대한항공 발송 및 전체 시험 완료 | 항공·시험 실행 로그 |

## 왜 10분 늦었는가

작업이 10분 동안 실행 중이었던 것이 아니다. 15:15에는 아예 실행되지 않았고, 15:25에 사용자가 PC를 깨우자 2초 만에 시작됐다. `StartWhenAvailable`은 예약 시각을 놓친 작업을 PC가 다시 사용 가능한 상태가 되었을 때 실행하는 옵션이다.

## 가장 유력한 원인

예약 작업에는 `WakeToRun`이 설정돼 있었지만 현재 Windows 전원 계획에서 깨우기 타이머가 허용되지 않았거나 Modern Standby가 해당 타이머를 활성 깨우기로 처리하지 않았다. `powercfg /lastwake`도 예약 타이머 기록 없이 0을 표시했고, 실제 복귀 원인은 마우스였다.

## 수정 사항

1. 관리자 등록 시 AC 전원과 배터리 전원 모두 `RTCWAKE`를 명시적으로 활성화한다.
2. 매일 07:50 SYSTEM 권한의 깨우기 전용 작업이 먼저 PC를 깨우고 실행 상태를 유지한다.
3. 08:00 반도체 작업을 실행한다.
4. 08:20 대한항공 작업은 당일 반도체 `SUCCESS`를 확인한 뒤 실행해 카카오 메시지 혼합을 방지한다.
5. 다음 시험은 SYSTEM 깨우기와 실제 발송을 1분 간격의 별도 작업으로 등록해 깨우기와 발송을 독립 검증한다.

## 되는 조건

- PC가 완전 종료가 아니라 Modern Standby 또는 최대절전 상태다.
- 배터리가 방전되지 않았다.
- Windows 전원 계획에서 깨우기 타이머가 허용돼 있다.
- 로그인 세션이 유지돼 있다.
- 복귀 후 인터넷 연결과 카카오 인증 서버 접속이 가능하다.

## 안 되는 조건

- PC가 완전 종료됐다.
- 펌웨어 또는 Windows 전원 정책이 예약 타이머 깨우기를 차단한다.
- 사용자가 로그아웃했다.
- 네트워크가 장시간 연결되지 않는다.
- 카카오 토큰 갱신 또는 외부 서버 연결이 실패한다.

## 다음 검증 방법

`Fix-Wake-And-Test-Admin.cmd`를 관리자 승인으로 실행하면 현재 시각 기준 15분 뒤 SYSTEM 깨우기, 16분 뒤 두 리포트 순차 발송 시험이 등록된다. 시험 뒤 아래 세 가지를 확인한다.

1. 예약 시각에 Kernel-Power 복귀 이벤트가 발생했는가.
2. 복귀 원인이 마우스가 아니라 예약 타이머인가.
3. 반도체 발송 완료 후 대한항공 발송이 시작됐는가.
